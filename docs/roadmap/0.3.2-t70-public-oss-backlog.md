## 1. 제품 우선순위

## 2. 공개 Issue와 내부 기록의 역할

| 기록 | 쓰는 곳 |
|---|---|
| GitHub Issue | 사용자에게 보이는 bug, UX friction, enhancement, 재현 가능한 false positive·false negative, 외부 기여자가 맡을 수 있는 단위 |
| `docs/conflicts.md` C-ID | 내부 정확성 기록, 정책 충돌, 실험 finding, 세밀한 기술 이력 |
| H-n | Human Decision: 제품 정책, release 범위 승인 |

공개 Issue와 C-ID는 필요할 때 서로 링크하지만 1:1 대응을 강제하지 않는다. Issue 제목은 내부 번호가 아니라 사용자 문제로 쓴다. 외부 기여자에게 H-n·C-ID 절차를 요구하지 않는다.
